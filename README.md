# 综测加分自评向导

一个纯前端的手机端工具：把学院《综合素质测评奖励加分项目实施细则》里**上百个加分项目逐条摆到学生面前**，
自动按细则算分（含封顶、同类取最高），并生成收集表要求的证明材料 PDF。

> 起因：综测加分细则动辄十几页、上百个条目，手算容易出错，而**算错的代价是单向的**——
> 报高了会被认定弄虚作假，取消全年评奖评优资格。把规则交给程序执行比交给记忆可靠。

## 它解决什么

学院收集表要交的是 **5 个数字 + 5 个 PDF**（德智体美劳各一组：一个总加分、一份证明材料 PDF）。

| 学生原本要做的 | 工具怎么处理 |
|---|---|
| 从十几页细则里找出所有可能有分的条目 | 逐条列出全部项目（本项目为 159 项 / 136 屏），一条一条确认 |
| 手算每项分值，还要记住各种封顶 | 计分引擎按细则实现封顶、同类取最高、区间归档 |
| 把几十张证书照片排版成 PDF，每条配文字说明 | 选图 → 自动压缩 → 生成符合模板格式的 PDF |

---

## 功能

- **逐项自评**：按五育分 5 段推进，支持「本组全没有」整组跳过、清单视图批量勾选
- **自动计分**：7 种计分模式覆盖细则里的各种规则
- **材料清单**：答完自动生成「要交哪些证明」，可对着翻相册
- **生成 PDF**：手机端选图、压缩、生成，格式对齐学院《综测填写模板》
- **随时回改**：五育所有分组列一屏，点哪组改哪组
- **进度保存**：答题进度存 localStorage，中途被打断不丢

**数据全部留在浏览器里**，不上传任何服务器。项目没有后端。

## 快速开始

零运行时依赖，只需要 Node 跑测试。

```bash
git clone https://github.com/MOONFISH2233/Comprehensive-Assessment.git
cd Comprehensive-Assessment

node --test                      # 62 个单元测试
node test/verify-against-pdf.mjs # 把 159 个项目名拿回细则原文核对出处
python -m http.server 8000       # 起本地服务（ES modules 不能走 file://）
```

然后浏览器打开 <http://localhost:8000> ，按 390×780 手机视口查看。

## 几个非显然的设计决定

写在这里，免得后来的人（包括我自己）把它们当 bug 改掉。

### 1. PDF 里的中文是图片，不是文字

jsPDF 内置的 Helvetica 不含中文字形，`doc.text('德育加分')` 直接输出乱码。
嵌入中文字体要 5–10MB，而浏览器的 canvas 天生支持中文 ——
所以所有文字都经 canvas 渲染成图片再 `addImage`。

代价：PDF 里的文字不可选中、不可搜索。对「上传给评审组看」这个用途可以接受。

### 2. `addImage` 必须传 `'FAST'`

不传时 jsPDF 会把 PNG **解码成裸 RGB** 塞进 PDF，一张 180×6mm 的说明图能从 1KB 膨胀到 200KB。
实测同样内容：**5.35 MB → 254 KB**（21 倍）。

### 3. 「有」和「没有」是同等权重的按钮

把「有」做成高亮主按钮会让人下意识点它。而综测里**报高是危险方向**
（拿不出证明 = 弄虚作假）。所以两个都是中性按钮，逼人真的读一遍再选。

宁可少算也不往高报 —— 因此级别/等次没选全时，那一项按 0 分计，并在结果页显著提示。

### 4. 进度条是分段的，不是 136 步匀速

有实验表明匀速进度条几乎是所有方案里最差的（中途退出率 14.4%，和不显示一样），
而「先慢后快」最糟 —— 136 屏正好是这种。改成按五育分 5 段，文案说「剩余 3 组」而不是「还剩 100 屏」。

### 5. 计分引擎对脏数据是健壮的

把 `answers` 改成字符串、数字、数组都不会抛异常，只是算 0 分。
所以「存档损坏导致白屏」这条路基本不存在。

### 6. 出错要有兜底页

`render()` 外套了 try/catch，渲染失败时显示「页面出了点问题」+ 原始错误信息 + 重试/清空两条出路，
而不是白屏。给别人用的东西，这一条是必需的。

## 换一个学院/学校怎么用

核心是改 `catalog.js`：把你们细则里的加分项目按同样的结构抄一遍。
每个分组的形状：

```js
{
  id: 'D-sizheng',
  yu: 'D',                    // D 德育 / Z 智育 / T 体育 / M 美育 / L 劳育
  title: '思政教育活动',
  note: '每参加 1 次加 0.1 分，累计不超过 0.6 分。',
  cap: 0.6,                   // 封顶；null 表示不封顶
  mode: 'count',              // 见下方模式表
  unit: 0.1,
  items: [{ id: 'D-sz-1', name: '……' }]
}
```

| mode | 用途 |
|---|---|
| `count` | 逐项问有没有，每项记 `unit` 分（单项可用 `unit` 覆盖） |
| `items-grade` | 逐项问具名比赛，再选获奖级别和等次 |
| `grade` | 整组一屏，可添加多个奖项 |
| `honor` | 按「级别 × 角色（个人/负责人/成员）」勾选 |
| `pickmax` | 同一子类里只取最高分（四六级、普通话、计算机等级） |
| `range` | 分值由评审组认定，学生自填预期值 |
| `tier` | 按区间归档（志愿时长 10/20/30 小时三档） |
| `penalty` | 扣分项 |

改完跑 `node --test`：测试按组钉死了条目数、封顶值、分值表，漏抄一项会直接指出是哪一组。
`test/verify-against-pdf.mjs` 还会把每个项目名拿回 `细则原文.txt` 搜出处，防止抄错或编造。

## 已知限制

- **不做 OCR，不自动解析细则**。项目里的 159 项是从 PDF 逐条抄录并人工核对的
  （核对脚本抓出过把「证明资料」抄成「证明材料」这类错误）。
  自动解析任意格式的细则文档是另一个量级的问题，目前不在范围内。
- **只算加分，不算总分**。学业加权平均分（权重 65%）、体测、各项基础分由学校导入。
- **图片不落盘**。localStorage 存不下，刷新会丢已选图片（答题进度不会丢）。
- **无访问控制**。部署在作者自己的服务器上，链接被转发无妨 —— 站上没有任何人的个人信息。
