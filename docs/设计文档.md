# 综测加分自评向导 · 设计文档

日期：2026-09-24
用途：重庆大学国家卓越工程师学院 2026 下学期综合素质测评
截止：2026-09-25 17:59

---

## 1. 要解决的问题

学院给了一堆 PDF 细则，学生要交的是收集表上 10 个空：

```
4  德育（PDF）    5  德育总加分
6  智育（PDF）    7  智育总加分
8  体育（PDF）    9  体育总加分
10 美育（PDF）   11 美育总加分
12 劳育（PDF）   13 劳育总加分
```

即 **5 个 PDF + 5 个数字**。学生自己干这件事有两个真实的坑：

1. **算错分**。细则里满是封顶、同类取最高、两份文件数值打架，手算极易出错。
   而且填错了不是扣分那么简单——按通知第 5、7 条，重复加分按违纪作弊处理，取消当年全部评奖评优资格。
2. **拼 PDF 费时**。每育十几张图，要配 `【图片N】XX活动，加X分` 的文字说明，
   手机上手工排版很痛苦。

本工具把这两件事都接过来，学生只负责「翻相册、选图」。

## 2. 范围

**做：**

- 逐项问答，覆盖细则中**每一个具名加分项目**（约 160 项）
- 自动计分（含封顶、同类取最高、冲突标注）
- 手机端选图 → 压缩 → 生成符合模板格式的 PDF，每育一个
- 输出 5 个数字供抄录

**不做（YAGNI）：**

- 不做登录、不做后端存储。图片全程留在浏览器内，服务器上只有一个空工具页面，
  不含任何个人信息。
- 不做证书 OCR 自动识别（识别不准反而误导）
- 不计算总分。`z1`（学业加权平均分）与 `t1`（体测成绩）由学校导入，
  且收集表只要「加分」，工具只算加分部分。
- 不做跨学期。细则明令重复加分按违纪处理，工具只管 2026.03.02–2026.09.05 这学期。

## 3. 计分依据与冲突取舍

两份文件并存：

| 文件 | 定位 | 采用 |
|---|---|---|
| `国家卓越工程师学院2026下学期学生综合测评奖励加分项目实施细则.pdf` | 本学期具体项目清单 | **优先** |
| `国家卓越工程师学院本科学生综合素质测评办法及细则 (1).pdf` | 学校层面框架与公式 | 冲突时让步 |

**已发现的 4 处数值冲突**（工具按左列取值，并在界面标黄提示「此处两份文件不一致，建议问辅导员」）：

| 项目 | 学院细则（采用） | 学校办法 |
|---|---|---|
| 学院级竞赛一等奖 | 2 分 | 1 分 |
| 班长/团支书 | 0.5–2.5 | 0.5–1.5 |
| 校级社团学生干部 | 考核合格 0.5 / 优秀 1.0 | 0.5–2.5 |
| 宿舍文明卫生上限 | 0.5 分 | 0.6 分 |

**国际级**：细则只写「国家级」，学校办法写「国际级或国家级」。工具把二者并入同一档，
界面注明。

## 4. 计分引擎

### 4.1 公式（工具只算加粗部分）

```
D = d1×20% + d2 − d3      只算 d2 − d3
Z = z1×65% + z2 + z3      只算 z2 + z3
T = t1×80%×5% + t2        只算 t2
M = m1×5% + m2            只算 m2
L = l1×5% + l2            只算 l2
```

### 4.2 四类必须强制处理的规则

**① 封顶**（超出的部分不计分，界面明确提示已达上限）

| 项 | 上限 |
|---|---|
| 德育·思政教育活动 | 0.6 |
| 德育·社会服务（学生干部） | 2.5 |
| 智育·科技学术活动 | 0.6 |
| 体育·课外体育锻炼 | 0.6 |
| 美育·美育活动 | 0.6 |
| 美育·组织者 | 1.0 |
| 劳育·宿舍文明卫生 | 0.5 |
| 劳育·社会实践 | 0.6 |
| 劳育·志愿时长 | 0.3（按档计，非累加） |

**② 同类取最高**

- 同一比赛多个奖 → 取最高级别
- 四六级 / 计算机等级 / 普通话 → 同类只加最高一次
- 同一荣誉多个级别 → 取最高

**③ 需评审组认定（非固定值，工具让用户自填，不替其猜测）**

突出事迹（2.5–7.5）、社会服务（0.5–2.5）、自主创新创业（0.1–1）、
坚持体育锻炼（0.1–1）、美育组织者（0.1–1）。

**④ 不重复加分**

细则明确：**已加志愿时长的社会实践不再加社会实践分**。工具在「劳育·社会实践」
处对已标记志愿时长的用户给出警告。

### 4.3 扣分项（德育 d3）

必须问，否则算错：不假离校/无故缺课/晚归不归（0.1/次）、
纪律处分（学院通报 1.5 / 学校通报 2.5 / 警告 4 / 严重警告 6 / 记过 8 / 留校察看 10）、
其他违规（宿舍抽烟、熬夜打游戏，0.1/次）。

## 5. 交互流程

### 阶段一「盘家底」——逐项问答

约 160 屏，一屏一项，按 德育 → 智育 → 体育 → 美育 → 劳育 分 5 章。

每屏内容：进度（`37/160`）、所属分组、项目名称、细则原文的示例说明、
两个大按钮【有】/【没有】。选【有】时按该项类型弹出后续输入：

- 固定分值项（如「参加比亚迪校园跑 0.1 分」）→ 直接记分，可填次数
- 分级项（竞赛/荣誉）→ 选级别（国家级/省市级/学校级/学院级）与等次（一/二/三/优秀）。
  **此处必须内嵌「认章规则」提示**：落款章为「重庆大学」或「重庆大学党委」
  才是校级，其余落款章一律算院级。学生最容易在这里把院级当校级报高。
- 认定项 → 填自评预期值

**两个加速设计（不破坏「每项都问到」）：**

- **【本组全没有】**：整组跳过，弹出确认「确认这 50 项都没有？」防手滑
- **【列表视图】**：切成本组全部项目一次性勾选，方便回头补

答题进度存 localStorage（只存选项与分值，体积极小）。

### 阶段二「传材料」——按育生成 PDF

一次做一育，中途退出只丢这一育。每育：

1. 展示该育的【待找材料清单】，可截图带走
2. 逐条选图（`<input type="file" accept="image/*" multiple>`）
3. **压缩**：手机原图约 4MB，20 张即 80MB，PDF 传不动。
   用 canvas 缩到最长边 1400px、JPEG 质量 0.75，单张降至数百 KB
4. 点【生成 XX 育 PDF】→ 浏览器下载

### 阶段三「交表前自查」

通知里有 4 条硬性要求，学生自己容易漏。工具在生成 PDF 后逐条弹出确认：

| 要求（通知原文） | 工具的检查点 |
|---|---|
| 落款时间 2026.03.02–2026.09.05 | 每组选图时提示「这张图上的日期在区间内吗」 |
| 上学期已加分的奖项不重复加分 | 清单顶部固定红字警告（重复加分按违纪作弊处理） |
| 活动照片需要本人出镜证明 | 美育/体育/劳育活动类目的选图提示 |
| 劳育必须提供完整的志愿时长截图 | 劳育 PDF 生成前强制确认「志愿时长截图是否完整（含总时长数字）」 |

## 6. PDF 输出格式

严格对齐 `综测填写模板  .pdf`：

```
                      智育加分 = 2.3

                      1. 专业技能加分
【图片1】大学英语六级通过，加 1 分
【图片2】普通话二级甲等，加 0.3 分

                      2. 竞赛获奖加分
【图片3】XX竞赛校级二等奖，加 1 分
```

- A4 纵向，图片按序纵向排布，超出自动分页
- 每张图上方一行文字说明，编号连续
- 分类标题（`1. 专业技能加分`）加粗居中

## 7. 技术实现

- **单文件 HTML**，无构建步骤，直接丢服务器静态目录
- **PDF 生成**：jsPDF（CDN 引入）。`doc.save()` 在 Android Chrome 直接下载到
  「下载」目录；在 iOS Safari 会打开预览，需点「分享 → 存储到文件」，
  界面上给这一步提示
- **图片压缩**：canvas `toBlob`，异步逐张处理并显示进度
- **文件命名**：部署名用英文不可猜名（服务器无访问控制）

## 8. 验证方式

1. `Invoke-WebRequest` 确认返回 200 且字节数与本地一致
2. 浏览器按 390×780 手机视口截图，确认排版、无 console 报错
3. **计分正确性**：手工构造 3 组用例核对
   - 封顶用例：勾 10 项各 0.1 的思政活动 → 应为 0.6 而非 1.0
   - 取最高用例：同时勾四级与六级 → 应为 1.0 而非 1.5
   - 志愿时长用例：32 小时 → 应为 0.3
4. 实测生成一份带多图的 PDF，确认可下载、可打开、图片不糊

## 9. 已知风险

| 风险 | 处置 |
|---|---|
| 项目清单抄漏或抄错 | 交付前用脚本比对 PDF 原文与数据结构的条目数 |
| 两份文件冲突处取错值 | 已列于第 3 节，界面标黄，并在说明中建议问辅导员 |
| 160 屏太长用户中途放弃 | 本组跳过 + 列表视图 + 进度持久化 |
| iOS 下载 PDF 体验差 | 界面给出「分享→存储到文件」的图文提示 |
| 学院临时增补项目 | 每组末尾留「其他（自填名称与分值）」入口 |
